# Module `backend`

Complete AWS infrastructure of a kybes backend, generated from the kybes project (`schemas/openapi.yaml`, `services/<context>/functions|ms/<name>`, `jobs/<name>`, `schemas/db`). The stack passes the generated `handlers.auto.tfvars` (`handlers`, `routes`, `public_routes`), `jobs.auto.tfvars` (`jobs`) and `kybes.auto.tfvars` (`kybes_root`, `openapi_path`, `has_db`): regenerate them with `/kynfra:create-backend-infra-aws`, never edit them by hand (rule `api-coverage`).

| Area | What the module creates |
|---|---|
| REST API | `aws_api_gateway_rest_api` (REGIONAL) whose `body` is the kybes OpenAPI document read at every plan (`yamldecode(file(var.openapi_file))`, the schema stays the single source of truth), with every operation enriched with `x-amazon-apigateway-integration` (Lambda proxy to the `live` alias, or `VPC_LINK` HTTP proxy to the internal NLB for microservices, path parameters mapped), `x-amazon-apigateway-request-validator = "all"` (body and parameters) and the authorizer. An operation missing from `routes` falls back to its `x-kybes-handler`; a precondition fails the plan if an operation has no existing handler. |
| Authorizer | REST APIs have no native JWT authorizer (HTTP APIs do): `authorizer = "lambda"` (default) is a `TOKEN` authorizer on a Lambda that validates the OIDC JWT (`OIDC_ISSUER`, `OIDC_AUDIENCE` env; code shipped as `authorizer/authorizer.zip` in the artifacts bucket, out of the kit), `authorizer = "cognito"` a `COGNITO_USER_POOLS` authorizer on `cognito_user_pool_arn`. Defined as an OpenAPI security scheme, applied to every operation except those with `security: []` in the schema **and** listed in `public_routes` (from `public_routes` in `.kynfra/config.json`). |
| Stage | `api`: resources are the OpenAPI paths prefixed with the base path of `servers[0].url` (e.g. `/v1`) unless they already start with it, so the direct URL is `https://<id>.execute-api.<region>.amazonaws.com/api/v1/...` and the `spa` `/api/*` behavior forwards `/api/v1/...` unchanged (`api_origin_path = ""`); `routes` keys stay the raw schema paths. X-Ray tracing, JSON access log (`correlationId = $context.requestId`) to a KMS-encrypted log group, execution log group created upfront with retention, `aws_api_gateway_method_settings` on `*/*` with throttling, metrics and `INFO` logging, regional WAF (managed rule sets, anonymous IP list, per-IP rate limit, KMS-encrypted logs) with `waf_enabled` (mandatory in prod). The account-level API Gateway CloudWatch role (a per-account-and-Region singleton) lives in the shared stack `envs/shared/apigw-account`, generated with the pattern and applied once before the backend stacks. |
| Lambda | One per function (and the authorizer): runtime and handler from the function manifest, zip from the private versioned SSE-KMS artifacts bucket (S3 access logs to the backend logs bucket, SSE-S3 as S3 access logging requires; `artifact_keys`, `artifact_sha256s` from CI; default key `<context>/<name>.zip`), `timeout = 10`, X-Ray `Active`, JSON logs to a dedicated log group with retention and KMS, env vars encrypted with KMS and holding no secret (only secret ARNs, proxy endpoint, user), name and role name validated to 64 characters, dedicated role (own logs, X-Ray, read of the context secrets from the `secrets` stack via identity policy, `rds-db:connect` on the proxy), alias `live`, invoke permission restricted to the stage (or to the API authorizers). With `has_db` the functions run in the private subnets with a dedicated security group. |
| Microservices | Shared internal NLB (private subnets, cross-zone, deletion protection in prod, security group with no ingress and `enforce_security_group_inbound_rules_on_private_link_traffic = "off"`, egress only to the VPC on `ms_target_port`), one TCP listener (`10001`, `10002`, … or `ms_listener_ports`) and one IP target group per microservice (register the pods with an AWS Load Balancer Controller `TargetGroupBinding`), ingress on the EKS node security group from the NLB, `aws_api_gateway_vpc_link`, Pod Identity role per microservice (service account `<context>-<name>`). NLB access logs go to the backend logs bucket (they are written only for TLS listeners: for TCP traffic rely on API Gateway access logs and VPC flow logs). ECR repositories live in the shared `ecr` stack. |
| Jobs | Per job: SQS queue and DLQ (KMS, `maxReceiveCount = 5`, redrive allow policy), EventBridge Scheduler schedule writing to the queue for `trigger = "schedule"` (from `jobs/<name>/job.yaml`), Pod Identity role consuming its queue (service account `<job>`). KEDA scales with the operator role of the `eks` stack (`sqs:GetQueueAttributes` on `<project>-<env>-*`). |
| Database | With `has_db` (`schemas/db` present): RDS Proxy with end-to-end IAM authentication (`default_auth_scheme = "IAM_AUTH"`, no secret, `require_tls = true`) in front of an existing instance (`db_instance_identifier`, out of v1 scope, with IAM database authentication enabled, `iam_database_authentication_enabled = true` on the instance): Lambdas connect with an IAM token as `db_iam_user`, the proxy role connects to the database as the same user (`rds-db:connect` on the instance resource id); the user must exist for IAM authentication (`GRANT rds_iam` in PostgreSQL, `IDENTIFIED WITH AWSAuthenticationPlugin AS 'RDS' REQUIRE SSL` in MySQL/MariaDB). Engine families `POSTGRESQL` and `MYSQL` (also MariaDB): IAM_AUTH does not support SQL Server. Proxy security group reachable only from the Lambda security group. Allow the proxy security group on the database security group manually. |

Inputs: `project`, `environment`, `openapi_file`, `handlers`, `routes`, `public_routes`, `jobs`, `vpc_id`, `private_subnet_ids`, `secret_arns`, `secrets_kms_key_arn`, `context_secrets`, `authorizer`, `cognito_user_pool_arn`, `oidc_issuer`, `oidc_audience`, `authorizer_runtime`, `authorizer_handler`, `artifact_keys`, `artifact_sha256s`, `lambda_memory_size`, `log_retention_days`, `throttling_rate_limit`, `throttling_burst_limit`, `waf_enabled`, `waf_rate_limit`, `deletion_protection`, `eks_cluster_name`, `eks_node_security_group_id`, `kubernetes_namespace`, `ms_target_port`, `ms_health_path`, `ms_listener_ports`, `job_visibility_timeout_seconds`, `has_db`, `db_instance_identifier`, `db_engine_family`, `db_iam_user`.

Outputs: `api_id`, `stage_name`, `api_domain_name` (`<id>.execute-api.<region>.amazonaws.com`, read by the `spa` stack), `api_origin_path` (empty), `base_path`, `invoke_url`, `lambda_function_names`, `lambda_role_arns`, `artifacts_bucket`, `artifact_keys`, `kms_key_arn`, `queue_urls`, `queue_arns`, `dlq_urls`, `pod_role_arns`, `service_accounts`, `vpc_link_id`, `ms_target_group_arns`, `ms_listener_ports`, `ms_nlb_security_group_id`, `db_proxy_endpoint`, `db_proxy_security_group_id`.

The `backend` stack reads `network` (VPC and private subnets), `secrets` (`secret_arns`, `kms_key_arn`, one-directional), and with microservices or jobs `kubernetes` (`cluster_name`, `node_security_group_id`) and `envs/shared/ecr` (`repository_urls`, output as `workload_repository_urls`) through `terraform_remote_state`.
